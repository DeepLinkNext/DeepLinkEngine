# 固定 B0 镜像原件

B0 为 ARM64 `quay.io/ascend/vllm-ascend:v0.18.0`，原始 OCI manifest 为：

```
sha256:2467d259ff068ca4edd7b50b849152910f3c05e435f314639fc06bcc7a00f9fa
```

原始 manifest、配置和全部 17 个压缩层已封存到[本仓库 B0 Release](https://github.com/DeepLinkNext/DeepLinkEngine/releases/tag/b0-original018-oci-20261120-v1)，共约 5.93 GB。大 blob 按顺序分片；[索引](b0-oci.json)记录每片和完整原件的大小、SHA-256 与下载入口。

根目录一键评测自动准备这些原件，再交给既有冻结恢复器重建 B0。无需 Docker 服务，也不依赖测试时能访问 Quay 的 blob 服务。原始镜像、源码、二进制及镜像内使用条件均保留，恢复后仅应用已冻结的文本适配补丁。

原始包和结果使用配置的缓存及输出目录。包含大量小文件的 B0 运行目录优先在本机 `/tmp` 或 `/var/tmp` 的磁盘文件系统重建，避免 NFS 元数据操作拖慢首次启动；本机需有至少 40 GiB 空闲。可用 `DEEPLINKENGINE_B0_RUNTIME_CACHE` 指定高速盘目录。目录随容器丢失时，会从已校验原件重建；已采集结果仍保留在原输出目录。没有可用本机磁盘时，沿用配置中的缓存目录。

已存在且哈希相符的 OCI blob 优先复用。可通过 `DEEPLINKENGINE_B0_OCI_CACHE` 指定保存 `sha256-<digest>` 文件的目录。默认也检查 `~/.cache/vllm-hust-engine/b0-image-018`。本次缓存目录中已有的原件仍会校验，不重复下载。

完全离线时，将 Release 的分片下载到同一目录并设置 `DEEPLINKENGINE_B0_ARCHIVES=/path/to/b0-parts`。每片和重组后的原始 blob 均须通过校验，随后核对完整原始 manifest 清单。缺片、错序、损坏和额外 blob 均不能进入模型测试。

仅准备原件：

```sh
python baseline_bundle.py --cache /path/to/cache
```

若旧入口在安装完成后的准备阶段失败、尚未产生推理任务，可保留原配置恢复：

```sh
python run_all.py --config evaluation.json --resume-bootstrap
```

该模式先核对原配置，重新校验环境、安装包和运行时源码，保留失败收据及日志，并在新目录重做准备。已经存在推理任务时会拒绝此模式，避免重复运行或混用结果。

## 启动缓存与恢复

校验和恢复归档会形成文件缓存。一键入口在启动模型前，对已知 OCI 分片、blob 和安装轮包发送只读 `POSIX_FADV_DONTNEED` 提示，保存路径、文件身份及前后 cgroup 读数。不写文件内容、不清空全机缓存、不改变内存限制；模型启动仍要求原有 12 GiB 原始余量，运行中仍保留原保护门槛。文件系统不接受提示时保留错误，由原内存检查决定是否可启动。

若首个 `continuous-B0` 阶段在模型服务启动前失败，可以执行：

```sh
python run_all.py --config evaluation.json --resume-before-model
```

该入口要求封存记录明确证明服务与客户端均未启动、清理已完成、其余阶段均未执行；任何服务进程记录或已执行阶段都会拒绝恢复。旧输出、日志和报告移入 `attempts/`，原配置保持一致，原安装解释器重新核验后复用。此模式不会重复已经执行的推理。

B0 重建成功后自动移除本机磁盘上约 5.93 GB 的压缩中转副本；运行 SDK 不使用这些副本，配置缓存中的已验哈希原件全部保留。重建失败时保留中转文件。此步骤同时避免部分 overlay 文件系统忽略缓存提示后仍将中转写缓存计入容器内存。

当 SDK 校验重新填充缓存、只读提示后仍不足 12 GiB 时，测试工具 v6 仅在模型进程创建前尝试有界回收。它要求完整、有效的 cgroup 计数，排除共享内存、全部映射页、锁定页、脏页和回写量；准备阶段可回收干净的活跃及非活跃文件缓存，并据此计算临时分配上限，临时私有匿名页最多 16 GiB，全部释放后再执行原始内存检查。原 64 GiB 容器限制、4 GiB 运行余量和 12 GiB 启动余量不变，任何新增 OOM 都失败。无效计数最多观察三次，持续异常则拒绝抵扣缓存。加载后、预热和正式计时路径不执行临时回收。

`checkpoint-cache-startup.json` 保存回收前后、临时内存上限、OOM 事件及原保护判定所用的观测。下载的工具包与仓库源码逐文件一致，CI 同原冻结包比较，限定修改为启动控制、缓存辅助函数及其回归测试三处文件；模型、题单、评分、预热和计时实现保持原哈希。
