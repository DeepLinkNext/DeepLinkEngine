# R9：书生模型适配与稳定版跟随

版本为 `vllm-hust-engine==2026.11.19.9.post1`，冻结标签为 [full-answer-b1-20261119-r9](https://github.com/vLLM-HUST/vllm-hust-engine/releases/tag/full-answer-b1-20261119-r9)。[公开运行包与哈希清单](https://github.com/vLLM-HUST/vllm-hust-website/releases/tag/engine-wheels-r9-v1)保留真实 CPython3.12/Linux ARM64 wheel 标签。

`.post1` 仅补齐 PyPI 包的 Markdown 说明元数据；SDK 和三个运行 wheel 与 R9 原件相同，冻结标签保持不变。

环境为双昇腾 910B2、CANN 9.1.0、Torch 2.13.0+cpu、Torch-NPU 2.13.0rc1、Triton-Ascend 3.6.0、Transformers 5.14.1。服务支持原 Qwen3.5-35B-A3B 和 BF16 Intern-S2；由发行包选择模型适配器，Qwen 原 worker 和继承的执行核心保持不变。固定测试仍核查模型、数据和基线来源，不把不适用的 Qwen 基线替换成书生基线。

书生在同一双卡环境完成 MMLU200 及 C8 连续 4K/16K 测试，与此前公开的 R8 数据比较如下。

| 场景 | 书生吞吐 token/s | 平均首 token 延迟变化 | 吞吐变化 |
| --- | ---: | ---: | ---: |
| MMLU200 | 1460.406 | -4.41% | +1.00% |
| C8 4K | 369.684 | -14.24% | -4.46% |
| C8 16K | 158.040 | -7.24% | -1.00% |

MMLU 正确 162/200，无失败或无法解析的响应。取舍仍保留：4K 平均 TPOT 增加 7.53%，4K 首 token 延迟 P99 增加 27.21%，16K 首 token 延迟 P95 增加 8.85%。完整数据见[上游实测说明](https://github.com/vLLM-HUST/vllm-hust-engine/blob/main/validation/r9/native-published-reference-v20.md)。这些是单模型集成验证，不是 Original018 B0/B1、完整五项或最终项目验收结果。

安装和新测试默认从官方 PyPI 解析最新稳定版，保留整轮版本记录；`--engine-version` 或配置 `engine_version` 可指定历史稳定版。已有测试的恢复及报告复算沿用原记录。测试客户端保留 R8 的封存原件、参考算力流程和启动内存修复，在单独的带哈希目录中加载选定发行包的模型/几何适配及 MOD 清单，不修改历史封存目录。
