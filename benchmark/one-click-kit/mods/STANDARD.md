# MOD整理与默认B1升级

稳定收益的技术要有可复算的模块入口；在当前B1上验证更好、更稳定的实现，通过集成验收后进入下一版默认B1。模块文档、原始对照和历史版本继续保留。

## 每个模块记录什么

| 内容 | 必须保留的信息 |
|---|---|
| 实现 | 源码入口、文件哈希、引擎与依赖版本、激活方式、关闭或恢复方式 |
| 条件 | 芯片、模型、精度、并行方式、输入输出预算、并发与到达方式、预热和编译边界 |
| 资源 | 设备与主机内存、锁页预算、缓存与预热成本，是否引入常驻缓冲区 |
| 完整结果 | 每轮吞吐、TTFT/TPOT及P95/P99、耗时、输出token、正确/截断/未解析/缺失数、逐题翻转 |
| 可复现性 | 冻结配置、命令、原始请求与响应、日志、封存清单、复算脚本、Release和取舍图 |
| 失败与组合 | 失败、负收益和未执行项；与其他MOD的依赖、冲突以及实际验证过的组合 |

单算子数值验证、完整模型性能、集成回归分别展示。同一固定200题的重复轮次仍以每轮200题为分母；输出token变化和正确数变化同时显示。

## 什么时候进入默认B1

1. 测量前固定对照、顺序、预算、判断阈值和完整任务分母。保留失败轮次；不靠缩短输出、删题、重复失败题或放宽阈值获得收益。
2. 验证实际原生执行路径的数值、异步源对象寿命、流与消费栅栏；两侧使用同一预热策略，测量期间检查运行时编译。
3. 用重复的完整模型对照检查收益、尾延迟和质量。只有吞吐提高但延迟或质量存在代价的配置，标明适用条件并提供取舍图。
4. 将实现集成到新版本，重新通过原生数值、上下文稳定性和完整任务验收。通过后更新默认配置、一键入口、Release和网站；原始版本与报告按日期保留。
5. 已被默认B1吸收的能力成为后续实验的共同基线。保留历史关闭对照用于复算；不从新基线移除该能力再重复计算旧收益。

单项收益不能相乘来代替组合测试。容量36与异步拷贝在r6上的独立结果，不能写成r7组合实测。质量正确数有波动时保留逐题对照，不把token一致或整数内核验证写成任务正确率等价。

## 已启用组件必须完整登记

基线已经使用的 BetterScale、Microflow、KV materialization、M01 correction、packed-host、Extension Manager 和预热机制也纳入 mods/，不能只登记新探索成果。当前完整组合见 [r6 已启用栈](active-stack-r6.json)。

每项提供 README 与 mod.json，明确冻结 profile、实际部署目录、入口哈希、恢复来源、启用路径、依赖和资源成本。源码可以继续保留在冻结原包或已有 overlays；模块目录统一索引到唯一权威来源。引擎执行模式、底座和支持库分别记录，避免重复拆出虚构模块。吸收进默认组合的能力不作为可随意关闭的搜索维度；新的默认 profile 必须同步更新启用栈，实验候选不自动进入默认组合。
