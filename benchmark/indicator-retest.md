# 4.1 与 4.3 第三方现场测试

课题四按 V5 和相应验收阶段，在第三方见证下现场执行全部规定工况。正式判定只使用当次现场采集的数据。冻结的模型、题单、回放清单和脚本用于重现工况，历史测试记录不得复用。

## 4.1 同工况有效算量

| 项目 | 现场要求 |
| --- | --- |
| 工况 | Qwen3.5-35B-A3B、BF16、TP2、同一对昇腾 910B2、同一份 MMLU-Pro 200 题，每题输出上限 256 token。预热后做进程内双卡同步计时，B0 和冻结 r8 B1 现场各完整运行三轮。 |
| 采集 | 冻结模型、分词器、请求身份和生效配置。采集前排空异步搬运，并按协议重置检查点与前缀缓存，验证落盘。每轮实测 T 使用独立的无采集开销运行取得。另按相同请求与边界采集预填充、解码、动态专家及草稿依赖，求有效算量 F 的上下界。现场执行独立组件标定，建立资源约束依赖图，归档每轮参考时间下界、逐轮双卡同步计时和采集起止回执。 |
| 计算 | 每个节点 E(v)＝d(v)＋max E(前驱)，无前驱时取 d(v)。全图最大的 E(v) 是该轮参考时间下界。实测有效算力下界＝三轮有效算量下界之和÷（2×三轮实测时间之和×10¹²）。参考算力上界＝三轮参考工况有效算量上界之和÷（2×三轮参考时间下界之和×10¹²）。有效算量相同时可约去，效率下界直接用三轮参考时间下界之和除以三轮实测时间之和。 |
| 判据 | 里程碑按未经舍入的效率下界与 50% 比较。算量、计时、独立参考和现场配置须对应同一工况及轮次。某轮不完整时，在同次现场测试按同一工况重跑该轮。 |

根目录的 `run_all.py` 涵盖固定五项和长上下文／四租户。4.1 的现场进程内三轮计时、全模型有效算量及独立参考标定另行执行并归档；只有这三类当次证据齐备后才能判定 4.1。

## 4.3 长上下文稳定性

| 项目 | 现场要求 |
| --- | --- |
| 里程碑工况 | B0 和 B1 现场均运行 4K（4096–8191 token）和 16K（16384–24575 token）两档。两臂共用固定的五项 Terminal-Bench 2.1 任务及各档请求清单和哈希，使用同一对卡。并发 8 闭环，预热 60 秒，正式提交 300 秒后排空，固定输出 256 token。单请求超时 600 秒，关闭自动重试。 |
| 采集 | 预热前验证输出卷可写并记录剩余空间和 inode。归档逐请求的起止时间、状态、输出量、结束原因，逐窗完成数，服务和工作进程日志，进程退出与清理回执，主机和芯片异常事件以及日志采集覆盖情况。 |
| 里程碑判据 | B1 的 16K/4K 整段吞吐 ≥50%，TTFT P95、P99 比值各 ≤3.00，TPOT P95、P99 比值各 ≤2.00。纳入判定的档和窗口须有有效样本，计算分母为正。超时、失败、漏回、OOM、死锁、非预期退出、静默截断均为 0。日志写入失败或覆盖缺失时，该档记录无效，修复后在同次现场测试按固定清单完整重跑。 |
| 结题工况与判据 | 结题时 B0 和 B1 现场运行 32K（32768–49151 token）。B1 五个 60 秒窗口内，同一指标最大值÷最小值须满足吞吐 ≤1.50，TTFT P95、P99 各 ≤2.00，TPOT P95、P99 各 ≤1.25，并满足同一异常门槛。 |
