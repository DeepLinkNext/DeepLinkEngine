# 4.1 与 4.3 封存复核及补测

## 4.1 同工况有效算量

本轮 native/out256 补测已完成六轮计时、必要算量核验和原完整参考分母复算，B1 达成率下界 **89.7838%**，同口径 50% 里程碑通过。[本轮报告及独立复算](reports/r8-compute-reference-20261119-v1/README.md)。以下 HTTP/out8192 记录保留原有未完成状态；两种工况不混用。

复查了 r8 HTTP/out8192 的三次参考尝试、GDN prefill 组件包、M01 原型及时间线准备包。第三次尝试完成了 12 个 GDN decode 和 18 个 GDN prefill 组件案例。全模型采集启动返回 HTTP 500，启动回执指出须排空 State DMA、清理主机检查点和重置前缀。正式客户端未启动。该包的算量目录只有启动回执，缺全模型有效算量产物。组件数据可作独立标定输入，适用性按算子形状、精度和设备核验。[封存复核摘要](../evidence/indicator-retest-evidence.json)

已复算的历史 out256 配对效率下界为 B0 22.5173%、B1 59.7573%。冻结 r8 的 4.1 保持 V5 的进程内 out256 工况。[历史逐轮计时、算量与参考](reports/m01-qualified-pair-20261103/README.md)

| 补测项 | 要求 |
| --- | --- |
| 工况 | Qwen3.5-35B-A3B、BF16、TP2、同一对昇腾 910B2、同一份 MMLU-Pro 200 题且每题输出上限 256 token。预热后在进程内双卡同步计时。每个验收臂三轮。工况、版本、题单和计量边界一致且记录齐全的轮次可复用。本轮冻结 r8 已补齐该 native/out256 记录，逐轮原件及适用范围见上方报告。 |

## 4.3 长上下文稳定性

原包八个正式阶段的逐请求记录均完整返回，HTTP 状态均为 200，每次按预算正常结束并输出 256 token。B1 长上下文 4K、16K、32K 分别完成 248、169、98 条。两臂的 cgroup OOM 和 OOM kill 计数增量均为 0。B1 服务日志有 381 条 ENOSPC，其中 379 条带 Python 日志写入 flush 调用栈。可定位到 B1 的 4K、16K、32K 正式窗口，日志不足以证明分类异常均为零。四租户的请求量和计费窗口仍按其专项记录复核。[封存复核摘要](../evidence/indicator-retest-evidence.json)

| 补测项 | 要求 |
| --- | --- |
| 工况 | 里程碑补 B1 的 4K、16K 两档。沿用已冻结的相同五项 Terminal-Bench 2.1 任务及各档请求哈希。输入范围分别为 4096–8191、16384–24575 token，并发 8 闭环，预热 60 秒，正式提交 300 秒后排空，固定输出 256 token，单请求超时 600 秒，关闭自动重试。同一 B1 版本、同一对卡完成两档。已有 B0 记录按同工况及证据完整性核验后复用。 |
| 采集 | 采集前验证输出卷可写并记录剩余空间和 inode。保留逐请求时间、状态、成功输出量、结束原因及逐窗完成数，连续归档服务和工作进程日志、进程退出与正常清理回执、主机及芯片异常事件。记录采样覆盖、空档和日志写入错误。 |
| 判据 | 16K/4K 整段吞吐 ≥50%，TTFT P95、P99 比值各 ≤3.00，TPOT P95、P99 比值各 ≤2.00。正式请求超时、失败、漏回、OOM、死锁、非预期退出、静默截断均须为 0。日志写入失败或覆盖缺失时，按未取得完整异常证据处理。 |
| 结题 32K | 如需用当前版本支撑结题，32K 按 32768–49151 token 及相同五窗规则单独复测。已有 TTFT P95 五窗最大÷最小 **2.1914**，超过 2.00。结题门槛为吞吐比值 ≤1.50，TTFT P95、P99 比值各 ≤2.00，TPOT P95、P99 比值各 ≤1.25，并满足同一异常门槛。 |
