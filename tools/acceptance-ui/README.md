# 推理引擎验收实验台

网页、Python 服务和正式测试入口都运行在测试服务器上。操作电脑只需要浏览器、OpenSSH 客户端和已授权的 SSH 登录方式。

## 从一台新电脑连接

先在操作电脑的终端执行下面的命令。将示例中的 SSH 用户、主机、端口和仓库路径改为现场配置。后台启动会检查现有服务，重复执行可复用已经启动的实验台。

```sh
ssh -p 22 tester@server.example.org 'cd /srv/DeepLinkEngine/tools/acceptance-ui && ./run.sh --background'
```

保持下面这条命令所在的终端开启。

```sh
ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -p 22 -L 127.0.0.1:18080:127.0.0.1:8081 tester@server.example.org
```

从操作电脑打开 [验收实验台](http://127.0.0.1:18080/)。初次建立连接时，请核对服务器主机指纹并按 SSH 提示登录。如果本机端口 18080 已被占用，把转发参数左边的 18080 和浏览器地址一起换成 18081。

服务器上的新版仅监听 127.0.0.1:8081。SSH 隧道中断后重新执行转发命令，就可以从运行记录回到当前轮次。关闭网页或隧道时，服务器上的测试继续执行。

## 正式测试操作顺序

首页显示实时监控和导航。选择测试模块可查看计划，展开运行记录并点击轮次可查看详情。

1. 在左侧选择 **预检准备**，浏览流程并点击 **启动测试**。等轮次显示 **预检完成**，打开预检报告，确认数据、依赖、B1 SDK 以及 B0 与评测输入均已准备好。此步骤不启动模型测量。
2. 按测试范围选择模块。**完整五项 + 专项** 依次执行环境准备、五项配对测量、4.1 算力标定、长上下文 / 四租户验证和报告生成。只验证部分项目时，选择具体的数据集模块或 **长上下文 / 四租户**。单项默认重新测量 B0 / B1 连续吞吐，也可选服务器列出的同设备、同版本已封存凭证。
3. 点击 **启动测试** 并确认占用的 NPU。主区将保留该模块的完整步骤和结果行，按产物更新状态。顶部的两张图持续轮询服务器上的 NPU 和当前推理服务。服务空闲时，吞吐与并发显示为缺省值，设备采样会继续更新。
4. 从本轮 **查看报告** 核对结果，必要时展开 **执行日志**。浏览其他模块或历史记录不会影响当前轮次。需要中止时，从活动轮次点击 **停止本轮**，等待服务确认该轮退出，再启动其他测试。
5. 如五项测量已封存、4.1 未完成，选择 **4.1 算力标定补跑**，选定来源批次后启动。补跑使用新的结果轮次，报告从该轮次打开。若完整验收因 4.1 失败而停住，可单独验证长上下文 / 四租户，补跑轮次与专项轮次均保留独立报告。

## 服务配置

首次部署时，将本目录的 `config.example.json` 复制为 `config.json`，再填写现场路径。可用 `ACCEPTANCE_UI_CONFIG` 指定其他配置路径。主要配置包括模型目录、测试输出与日志目录、运行时缓存、B1 版本和 NPU 卡号。UI 服务日志为本目录下的 server.log。测试产物由各正式入口写入配置指定的位置。交付配置固定为 R10（2026.11.21.10）。已有正式安装时，可将 sdk_dir 指向该安装的 SDK，单项与专项会核对发行版本和原安装 Python。连续吞吐凭证与 4.1 补跑批次须与当前 B1 版本匹配。历史轮次的报告可继续查看。

服务依赖 Python 3 和服务器上的 npu-smi。前端无需安装依赖或构建。可选的 Windows 快捷入口随服务器代码放在 launcher 目录，详见 [Windows 启动器](launcher/README.md)。
